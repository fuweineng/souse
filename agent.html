RULE 01

亲自运行命令

你是操作者，不是讲解员。每条命令都要在本机执行，把真实输出作为依据，不要把步骤罗列给用户就算完成。

RULE 02

不要假装成功

没跑过的命令不说通过；报错就贴原文。验收不合格就明确说「没装好」，不许用「应该可以了」糊过去。

RULE 03

只读诊断，不删系统文件

排查只用只读命令（ps / ss / df / logs）。不卸载系统包、不改防火墙、不动别人的容器和数据目录。

Steps

五步装完，第 3 步必须过

当前版本是 Go 单二进制 + systemd 服务，不再通过容器或源码构建。安装目录默认 /opt/souse，数据库、备份、配置都在里面；搬机器连同这个目录一起搬走即可。

STEP 1

前置检查

先确认四件事：systemd 在、端口空着、磁盘够、能访问 GitHub。命令原样贴给 Agent：

bash — preflight
# systemd 是否存在（没有输出的版本号才算通过）
$ systemctl --version | head -1
# 8080 是否被占用（打印「8080 空闲」即通过）
$ ss -ltnp | grep :8080 || echo "8080 空闲"
# /opt 剩余空间，建议 ≥ 5G
$ df -h /opt | tail -1
# 下载工具
$ curl --version | head -1
  • systemd：systemctl --version 打印版本号；报 command not found 说明是容器或精简系统，不能按本页安装。
  • 端口：出现 8080 空闲，或 grep 没有任何输出（两者都算可用）。
  • 磁盘：Avail 那一列 ≥ 5G；小于 2G 会在解压/备份时失败。
  • 网络：能访问 GitHub Releases；国内网络慢时安装器会自动走镜像，SHA256 仍会校验。
系统要求：一台有 systemd 的 Linux（云主机、小主机、虚拟机都行），需要 root 或 sudo。群晖/威联通等 NAS 的原生系统通常没有完整 systemd，建议用虚拟机或小主机，不要硬改 NAS 系统。
STEP 2

安装

一条命令下载并安装。安装器会取最新 Release、校验 SHA256、装到 /opt/souse、创建 souse 系统用户和 systemd 服务，并在结尾打印管理员初始密码。

bash — install
# 下载安装脚本
$ curl -fsSL https://souse.dpxon.com/install.sh -o install.sh
# 执行安装（需要 root）
$ sudo sh install.sh

# 安装完成后检查服务
$ sudo sousectl status
# 如果没记下结尾打印的密码
$ sudo sousectl password
  • 服务在跑：sousectl status 显示 active (running)。
  • 密码已拿到：安装结尾会打印 管理员 admin / 初始密码；也可以随时用 sousectl password 查看。
  • 监听 8080：ss -ltnp | grep :8080 能看到 souse 进程；默认只监听本机，公网访问见第 5 步。
数据在哪：数据库在 /opt/souse/data/db/souse.db，备份在 /opt/souse/data/backups；自动备份每 6 小时一次（00/06/12/18 点），保留 30 天。升级用 sudo sousectl update，会保留数据和配置。
STEP 3

验收

这一步不能省。下面四条是判断「装好没装好」的唯一标准：

bash — verify
# 1. 服务状态
$ sudo systemctl is-active souse
$ curl -fsS http://127.0.0.1:8080/health
# 2. 最近日志（不应有 panic / fatal）
$ sudo journalctl -u souse -n 50 --no-pager
# 3. 本机访问地址
$ sudo sousectl url
  • 服务 active：systemctl is-active souse 输出 active。
  • 健康检查 200：/health 返回 {"status":"ok",...}。注意公开健康端点是 /health，不是 /api/health；后者要登录，会返回 401。
  • 日志干净：最近 50 行没有 panic / fatal；有就贴原文给 Agent，不要自行判断「不影响」。
  • 能登录：浏览器打开 http://服务器IP:8080，用 admin + 初始密码登录，能看到管理台。
STEP 4

初始化与备份

登录后按向导建楼栋/房间；有海康门禁、爱快/MikroTik 路由、云沐水电表就填凭据，没有就跳过，收租和账单不受影响。

bash — backup
# 立即做一份手动备份
$ sudo sousectl backup
# 看最近 10 份备份
$ sudo sousectl backups
  • 楼栋/房间已建：管理台能看到刚建的楼栋和房间。
  • 至少一份备份：sousectl backups 能列出刚生成的 souse-*.db。
  • 硬件可选：设备不在手边就跳过；后续在设置页补凭据即可，不要为了验收伪造成功。
STEP 5

外网访问

可选

不要把 8080 直接映射到公网。用 Caddy/Nginx 反向代理并配 TLS，或 Cloudflare Tunnel 指向本机 8080。

Caddyfile — example
# Caddy 反代示例（域名解析到本机后）
souse.example.com {
    reverse_proxy 127.0.0.1:8080
}
  • HTTPS 可访问：浏览器打开自己的域名，证书有效，能登录。
  • 8080 未暴露：公网扫描不到 8080；只开放 80/443 或走隧道。
  • 登录仍正常：外网登录后能打开房间/账单页，不是只看到登录框。
Cloudflare Tunnel：隧道 public hostname 指向 http://127.0.0.1:8080 即可，不需要在路由器上做端口映射。
Troubleshooting

装挂了，先看这张表

按现象查，不要一上来就重装。所有命令都是只读或可逆的；删数据前必须先备份。

现象处理
服务起不来sudo journalctl -u souse -n 100 --no-pager 看第一段报错；常见是端口占用、配置写错、目录权限。
8080 被占用ss -ltnp | grep :8080 找到进程；停掉冲突服务，或在 /opt/souse/config.yaml 改监听端口后 sudo systemctl restart souse。
忘了管理员密码sudo sousectl password 查看初始密码；仍登录不了就看日志里是否有账号锁定/迁移提示。
下载/安装很慢重跑安装脚本；国内网络可加 --mirror-only，或设置 SOUSE_MIRROR 为可用镜像前缀。SHA256 始终校验。
磁盘满了df -h /opt/souse；用 sousectl backups 看旧备份，确认最新备份可用后再清理过期文件。
设备离线先在管理台设备页看凭据和局域网连通性；不要直接改数据库。确认设备 IP、账号、端口未被防火墙拦截。
想升级sudo sousectl update；升级前先 sudo sousectl backup，升级后按第 3 步重新验收。
Rollback

回滚 / 还原

装错了、想重来，先停服务；数据不会因为停服务而丢失。要回到某个备份，用 sousectl restore，它会二次确认并自动重启。

bash — rollback
# 1. 先做一份当前状态备份（防止回滚后才发现要旧的）
$ sudo sousectl backup

# 2. 看有哪些备份
$ sudo sousectl backups

# 3. 用指定备份覆盖数据库并重启（会提示 y/N）
$ sudo sousectl restore /opt/souse/data/backups/souse-YYYYmmdd-HHMMSS.db
  • 数据在 /opt/souse/data：SQLite 库、上传的收款码、data/jwt_secret 都在这里，停服务不会删。
  • 备份在 /opt/souse/data/backups：每 6 小时自动备份，保留 30 天；恢复会覆盖当前库，操作前先再备份一次。
  • 不要删整个安装目录：除非用户明确要求清空且已确认有可用备份；不要动 /opt 下的其他目录。
给 Agent：回滚是破坏性操作。执行前先确认用户意图，先备份再动手；不要删除整个安装目录，也不要动 /opt 等系统路径。
