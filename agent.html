RULE 01

亲自运行命令

你是操作者，不是讲解员。每条命令都要在本机执行，把真实输出作为依据，不要把步骤罗列给用户就算完成。

RULE 02

不要假装成功

没跑过的命令不说通过；报错就贴原文。验收不合格就明确说「没装好」，不许用「应该可以了」糊过去。

RULE 03

只读诊断，不删系统文件

排查只用只读命令（ps / ss / df / logs）。不卸载系统包、不改防火墙、不动别人的容器和数据目录。

Steps

五步装完，第 3 步必须过

全程只需要 Docker。安装目录自己定（示例用 ~/souse），数据、备份、密钥都在这个目录里，搬机器连同目录一起搬走即可。

STEP 1

前置检查

先确认三件事：Docker 在、端口空着、磁盘够。命令原样贴给 Agent：

bash — preflight
# Docker 与 compose 插件
$ docker --version && docker compose version
# 8080 是否被占用（没有输出以外的报错，并打印「8080 空闲」即通过）
$ ss -ltnp | grep :8080 || echo "8080 空闲"
# 当前目录剩余空间，建议 ≥ 5G
$ df -h . | tail -1
  • Docker：两条命令都打印版本号；docker compose version 报 unknown command 说明只装了旧版 compose，先装 compose 插件。
  • 端口：出现 8080 空闲，或 grep 没有任何输出（两者都算端口可用）；有进程占着就记住它，第 2 步会撞上。
  • 磁盘：Avail 那一列 ≥ 5G。镜像 + 构建缓存比较占地方，小于 2G 基本会 build 失败。
没有 Docker 时：让 Agent 按发行版装官方 Docker Engine + compose 插件，装完重跑上面三条。不要用系统自带的旧版 docker.io 凑数。
STEP 2

安装

取代码 → 配管理员密码 → 构建启动。第一次构建要拉镜像，通常 2–5 分钟，慢网络会更久，不要中途 Ctrl-C。

bash — install
# 1. 取代码
$ git clone https://github.com/fuweineng/souse.git
$ cd souse

# 2. 配置：至少设置管理员密码（必填）
$ cp .env.example .env
#    编辑 .env，把 S610_ADMIN_PASSWORD 改成你要的密码
#    S610_JWT_SECRET 可以留空：首次启动会自动生成并写入 data/jwt_secret

# 3. 构建并启动（首次会拉镜像，耐心等）
$ docker compose up -d --build

# 4. 等健康检查变 healthy
$ docker compose ps
  • 密码已设置：grep S610_ADMIN_PASSWORD .env 不是空值；空着服务起不来或无法登录。
  • 容器在跑：docker compose ps 里 souse 的状态先是 Up (health starting)，等 30–60 秒再看应变成 Up (healthy)。
  • 端口绑定：服务监听 8080，compose 里绑 127.0.0.1:8080——只对本机回源，公网要靠 Caddy 或 Cloudflare 隧道（见第 5 步）。
数据在哪：业务数据在 ./data；自带 backup 容器每 21600 秒（6 小时） 热备 SQLite 到 ./backups，保留 14 天。这两个目录不要手动改，升级和搬家都靠它们。
STEP 3

验收

这一步不能省。下面四条是判断「装好没装好」的唯一标准，每条都给出「通过」长什么样：

bash — verify
$ docker compose ps
$ curl -sf http://localhost:8080/healthz && echo OK
$ ls -l data/jwt_secret
$ docker compose logs --tail=20 souse
  • 容器健康：docker compose ps 中 souse 那行是 Up (healthy)。只显示 Up、括号里是 starting，就再等 30 秒重看。
  • 健康端点：curl -sf http://localhost:8080/healthz && echo OK 必须打印 OK。连接被拒、超时、什么都没打印，都是失败。
  • 密钥已持久化：ls -l data/jwt_secret 能看到文件（不是 No such file）。这说明 JWT 密钥已生成并落盘，重启不会把登录态全踢掉。
  • 日志干净：docker compose logs --tail=20 souse 最近 20 行里没有 panic / fatal。有就贴原文，别自己判断「不影响」。
任意一条不通过，就是没装好，不要宣布成功。把失败命令和它的原始输出一起交给用户，再按下方「失败对照」处理。
STEP 4

配置向导

浏览器打开 http://<主机>:8080，首次访问会自动弹出 6 步向导。超管走完整 6 步；房东 / 助手账号只走「楼栋房间 + 水电表」两步。

完成判定：楼栋房间 + 收款码 两项配齐，系统即判定向导完成（completed=true），可以开始收租。其余步骤都是可选的。

必做两项 核心

  • 楼栋房间：楼栋名称、房间号、租金。这是整个系统的骨架，没有它账单和房态都无处落脚。
  • 收款码：上传微信 / 支付宝收款码图片，住户扫码付款时看到的就是它。

可选三项 有就配，没有就跳过

  • 水电表（云沐 iyunmu）：填 iyunmu_username / iyunmu_password。配好后对着表拍照即可 OCR 抄表、自动算费。没有云沐表就跳过——读数手填，账单照常生成，核心功能不受影响。
  • 爱快路由：填 ikuai_host / ikuai_username / ikuai_password。配好后欠费断网、缴费恢复、按房间限速。源码注释写明这一步「可选」。没有爱快就跳过——宽带账号手工登记；MikroTik / RouterOS、TP-Link 同样支持，在设置里选对应类型。
  • 海康门禁：填 hikiot_app_key / hikiot_app_secret，支持 ISAPI 直连，或走海康云眸开放平台 + WebConsole。没有海康门禁就跳过——门禁功能不启用，收租、账单、合同、住户手机页一切照旧。

STEP 5

外网访问

可选

默认只监听 127.0.0.1:8080，本机可用、公网进不来。要让住户和自己在外面访问，用 Cloudflare 隧道，不开放任何入站端口。

bash — tunnel
# 先在 .env 里填 CLOUDFLARE_TUNNEL_TOKEN
$ docker compose --profile tunnel up -d
  • token 已配：grep CLOUDFLARE_TUNNEL_TOKEN .env 有值，否则隧道容器会反复重启。
  • 隧道在跑：docker compose ps 能看到 tunnel 容器 Up；Cloudflare 面板里隧道状态为 Healthy。
  • 不需要隧道就跳过：只在内网用，或前面已有 Caddy / Nginx 反代，这一步直接略过，不影响验收。
Troubleshooting

失败对照表

Agent 遇到报错先查这里，按「现象 → 处理」走；处理完回到第 3 步重跑验收，不要跳过验收直接说好了。

现象怎么确认怎么处理
8080 被占用 ss -ltnp | grep :8080 能看到别的进程 先停掉占用进程；或在 .env 改 SOUSE_PORT 后重新 docker compose up -d。
镜像拉不动 卡在 Pulling / timeout / TLS 错误 重试；换网络或配置镜像加速；先 docker pull 再 docker compose up -d --build。
build 失败 退出码非 0，日志里是编译或磁盘错误 看 docker compose logs；用 df -h . 确认磁盘；核对 Docker 版本是否支持 compose 文件。
页面打不开，但容器 healthy curl -sf http://localhost:8080/healthz 本机能通，浏览器连不上 端口绑的是 127.0.0.1：从本机访问，或配 Cloudflare 隧道（第 5 步）。
向导没弹 打开直接进登录页 / 工作台 登录后到「控制台 → 系统设置」里重新运行向导。
/mcp/sse 返回 401 请求被拒，日志提示缺 token S610_MCP_SECRET 非空时，/mcp/sse 要求带 X-MCP-Token 头；补上或把该项留空。
Rollback

回滚 / 还原

装错了、想重来，停掉容器就行，数据不会丢。重新 docker compose up -d 就能回到原来的状态。

bash — rollback
# 停掉并移除容器（保留数据目录）
$ docker compose down

# 想彻底重来：先备份，再删 data/（这一步会丢数据，非必要别做）
$ cp -a data backups/manual-$(date +%F)
  • 数据在 ./data：SQLite 库、上传的收款码、data/jwt_secret 都在这里，down 不会删。
  • 备份在 ./backups：backup 容器每 6 小时热备一次，保留 14 天；要恢复，停服务后用备份文件替换 data 里的库再启动。
  • 不要用 docker compose down -v 清数据：除非用户明确说要清空，且已确认有可用备份。
给 Agent：回滚是破坏性操作。执行前先确认用户意图，先备份再动手；不要删除整个安装目录，也不要动 /opt 等系统路径。
